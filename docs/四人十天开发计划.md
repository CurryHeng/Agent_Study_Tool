# StudyForge 四人十天开发计划

## 角色分工

| 角色 | 代号 | 定位 | 擅长 |
|------|------|------|------|
| **A 前端** | FE | React/UI 组件 | 页面实现、交互、状态管理 |
| **B Agent** | AI | LLM/Agent 编排 | Prompt 设计、多 Agent 协作、API 对接 |
| **C 全栈** | FS | 前后端通吃 | API 设计、数据流、集成联调 |
| **D 数据** | DT | RAG/文档解析 | 向量数据库、文档管线、检索系统 |

## Day 3 — 出题流水线

| 谁 | 做什么 | 产出 |
|----|--------|------|
| A | 出题配置面板（选择章节/题型比例/数量） | 出题参数 UI |

## 风险与应对

| 风险 | 概率 | 应对 |
|------|------|------|
| LLM 出题质量不稳定 | 高 | 审核 Agent 兜底 + 人工审核入口 + 低质量题标记 |
| PDF 解析准确率不够 | 高 | AI 清洗作为第二步修正 + 用户手动纠错入口 |
| ChromaDB 性能问题 | 中 | SQLite FTS5 做 fallback，简单场景不依赖向量库 |
| 4 人并行开发代码冲突 | 中 | Day1 定好 API 契约 + Feature Branch + 每日合并 |
| 时间不够 P1/P2 做不完 | 高 | P0（前 5 天）必须交付，P1/P2 按优先级砍 |
