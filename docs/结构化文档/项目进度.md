### 3.2 导入 Agent 迁移（自 agent-quiz-feature，TS→Python 重写）

将另一开发者在旧 React/Express 栈实现的导入工作流移植到现架构（`backend/`）：

- **`services/structure_extract.py`**：中英双语规则引擎（语言检测 / 标题 / 粗体·「」术语 / 定义·对比·列表正则 / 段落级分块 / 术语匹配统计），0 次 LLM
- **`services/knowledge_extract_service.py`**：规则预提取、均匀抽样、短路判断、知识点三层校验、验证缓存（`parsed/{doc_id}.validated.json`）、LLM 块级提取（失败/解析异常均降级为空数组）
- **`workflow/import_graph.py`**：LangGraph 导入工作流
  `START →（无有效章节时）document_agent（LLM 章节理解）→ knowledge_agent（规则→抽样交叉验证→LLM 决策→必要时全量提取）→ validate（三层校验，失败回环 ≤2 次）→ END`
- **接入上传链路**：`document_service.upload_document` 仅在配置 `DEEPSEEK_API_KEY` 时运行增强；Document Agent 可重建章节；知识点经 `knowledge_service.import_knowledge_points` 挂入知识树（按章节标题匹配，去重；importance/difficulty 不入库）
- **同步延迟保护**：全量提取 LLM 调用上限 `MAX_FULL_EXTRACT_CHUNKS = 30`
- 移植时修正原实现两处问题：编号列表条目误取数字组导致被丢弃；提取 LLM 异常未捕获会击穿工作流
- 测试：`tests/test_import_agent.py` 16 例（规则引擎/分块/抽样/校验/图流程/LLM 故障降级/上传集成）
- 未迁移：图片视觉 OCR（对方用 deepseek-chat 当视觉模型实际不可用；待换千问视觉后单独做）
