## 六、整改顺序（优先恢复用户闭环 → 再架构优化）

**阶段 1：打通核心用户闭环（前端为主，后端小改）**

1. 内置题库可见：后端 `GET /workbooks` 增加返回系统工作簿(只读标志)，或前端 `QuestionBankView` 无过滤拉全部；`Dashboard` 直接展示全部题
2. 三种刷题模式 UI：参考 `QuizSession.tsx`（宽松/普通：计时+评分按钮+错因表单）与 `StrictSession.tsx`（模拟考试），复用后端已有的 `mode`/`rating` 字段与 `answer` 接口
3. 思维导图：引入 markmap 渲染（`markmap-view`/`markmap-lib`），并让系统内置题库的知识点可见
4. Agent 友好交互：按 `intent` 分流展示（出题→题目卡片；导图→图；chat→对话气泡），不再 `<pre>` JSON
5. Dashboard 完整：统计卡 + 章节分布 + 收藏入口 + 模式选择弹窗（参考旧 `Dashboard.tsx`）

**阶段 2：补齐题库/错题/账号闭环**

6. 题库：列表 + 添加题目表单（参考 `AddQuestion.tsx` 的错误档案/正确解析/总结结构）+ 编辑/删除
7. 错题本：错因编辑 + 按章节/错因筛选（参考 `QuestionCard.tsx` 错题对比 UI）
8. 账号：顶栏显示 username、设置页（API Key 绑定 `api_keys`、数据导出/重置）
9. KaTeX/markdown 渲染 + 收藏 + session 恢复 + 计时器（参考 `markdown.ts`、`sm2.ts`、`storage.ts`）

**阶段 3：Agent/后端架构优化**

10. Navigator → 完整规划器（多步任务 plan）；Review → 独立 Agent 节点；direct_answer → LLM 生成
11. short_answer LLM 判分；图片解析（千问视觉）
12. 去重 retry；RAG 删除接口；get_due 优化；事务边界（UoW/显式 commit）

**阶段 4：验证**

13. 前端 E2E（登录→题库→三模式刷题→错题→导图→Agent）；后端全链路回归

## 结论

后端骨架与数据模型基本到位、测试全绿，但**前端只完成了约 30% 的产品化**（缺三模式刷题、思维导图可视化、内置题库、题库/错题/账号完整闭环、Agent 友好交互），加上后端 **short_answer 判题与图片解析两个明确未完成项**，导致"测试绿但产品不完整"。

整改应从「内置题库可见 → 三模式刷题 → 思维导图 → Agent 友好化」这条核心闭环开始，再补题库/错题/账号，最后做 Agent 与架构优化。
