## 五、共享接口契约（Day1 定死，变更须在群里声明）

| 契约                       | 涉及    | 要点                                                                                                    |
| ------------------------ | ----- | ----------------------------------------------------------------------------------------------------- |
| 写操作 proposal 结构          | D↔A   | `{proposal_id, action, target, changes, impact}`；`POST /api/agent/confirm {proposal_id, approved}` 执行 |
| `/api/agent/chat` 响应     | D↔A   | 含 `reply` + `steps[]` + `proposals[]`；请求含 `context{view, selected_knowledge_id, ...}`                 |
| 错因字段 schema              | B↔A   | `{reason_type, explanation, suggestion}`，热力图按 reason_type 聚合                                          |
| 知识树编辑接口                  | C↔B   | C 的 PUT/DELETE 不得破坏 `import_knowledge_points`；删除沿用 SET NULL                                           |
| `/questions/generate` 响应 | B↔A   | 含每题审题结果（前端展示驳回原因）                                                                                     |
| LLMService               | B/C/D | 只加方法不改已有签名；prompt 常量放各自模块                                                                             |
| .env                     | A     | DEEPSEEK_API_KEY（文本）、QWEN_API_KEY（视觉），互不侵占                                                            |

## 六、Day 5 验收演示脚本

登录 → 上传 PDF →（自动索引+导图生成）→ 聊天让 AI 助手出 10 题（steps 可见）→ 确认提案入库 → 题库看审题结果 → 刷题故意答错（FSRS）→ 错题 AI 错因分析 → 热力图看薄弱点 → 聊天"把第三章改简单点"→确认提案 → 全程 pytest/vitest 全绿。
