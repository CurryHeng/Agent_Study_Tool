继续实现 GitHub issue #39：**主 Agent ReAct 化 + 工具层（核心）**。目标是将原固定意图路由图重构为 `create_react_agent` supervisor，增加 Service 薄封装工具、8 次工具调用熔断，并让 `/api/agent/chat` 返回可展示的 `steps`。

工作分支：`feat/p1-4-react-agent`。

## 已完成工作

### 1. 主 Agent ReAct 重构

- 将 `backend/workflow/graph.py` 从固定 Navigator/Orchestrator 路由图重构为 `create_react_agent`。
- 主 Agent 成为唯一开放式决策入口，具体业务仍通过工具和 Service 执行。
- 设置 `MAX_ITERATIONS = 8`，映射为 LangGraph `recursion_limit = 17`，避免工具调用死循环。
- 增加 supervisor system prompt，约束工具参数、写入行为和最终回复。

### 2. 新增工具层

新增 `backend/workflow/tools.py`，提供：

- `search_documents`
- `get_knowledge_tree`
- `get_knowledge_detail`
- `list_documents`
- `get_questions`
- `generate_questions`

工具绑定当前数据库会话和登录用户，权限检查复用现有 Service；工具本身不直接执行 SQL。出题参数强制要求语义明确的 `topic`。

### 3. 出题预览 Pipeline

- 新增 `generation_service.generate_preview`。
- 流程为：生成 → 三层校验 → 审核 → 最多 2 次重试。
- Agent 出题工具只返回预览，不直接写入题库，为后续 issue #40 两阶段确认保留边界。

### 4. steps 与接口兼容

- `agent_service` 从 `AIMessage` / `ToolMessage` 中提取工具名、参数、成功状态和摘要。
- `/api/agent/chat` 新增冻结契约字段：
  - `reply`
  - `steps`
  - `proposals`
  - `navigate`
  - `conversation_id`
- 暂时保留旧 `intent/result` 字段，避免当前 Dashboard 立即失效。
- AgentTask 日志保存完整结构化结果及工具调用步骤。

### 5. LLM 配置修正

- 发现 requirements 声明 `langchain-openai`，原代码却导入未声明的 `langchain-deepseek`。
- 改为通过 `ChatOpenAI` 连接 DeepSeek 的 OpenAI-compatible API。
- 新增 `LLM_BASE_URL` 配置，默认 `https://api.deepseek.com`。
- 本地 `backend/.env` 已配置真实 API Key，且确认被 Git 忽略；日志不记录密钥内容。

## 2026-08-16 续开发结果

- 根因定位：`question_validator` 复用 `CHOICE_TYPES` 时把 `true_false` 当成必须携带至少两个 options 的字母选择题，与生成契约“判断题仅使用 true/false 答案、不带 options”冲突，导致真实生成结果全部被确定性校验误过滤。
- 修复：只有 `single_choice` / `multiple_choice` 要求 options；判断、填空、简答携带 options 时仍会被拒绝。
- 新增判断题无选项的回归测试。
- `steps.summary` 改为结构化摘要，出题步骤可直接显示“生成并审核通过 N 道题；未保存”，避免重要字段被 200 字截断。
- `.venv/` 已加入 `.gitignore`；`python-multipart` 已加入 `backend/requirements.txt`。
- 真实 DeepSeek Pipeline：生成 3 道判断题，3 道全部通过审核。
- 完整 ReAct 验收：主 Agent 依次读取资料/知识点并调用 `generate_questions`，生成并审核通过 10 道判断题。
- 数据安全验证：验收前后内置题库均为 22 道，确认预览未写库。
- 最终验证：Ruff 通过；后端 `165 passed`；`/api/health` 返回 200；前端类型检查和生产构建通过。
