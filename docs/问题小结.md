一、项目整体结构
技术栈
- 后端：Python 3.11 / FastAPI / SQLAlchemy 2.0 / Alembic / LangGraph / Chroma / bcrypt / PyJWT / DeepSeek（langchain_deepseek）
- 前端：Vue 3 / TypeScript / Vite / Tailwind 3 / Pinia / vue-router / markmap / KaTeX / lucide-vue-next
- 数据库：SQLite（backend/data/quiz-app.db）+ ORM SQLAlchemy（声明式），向量库 Chroma
分层结构
frontend/src (Vue3)
  api/{client,index}.ts   → fetch 封装 + Bearer token + 自动 refresh
  stores/auth.ts          → Pinia
  views/*.vue             → 11 个页面
  router/index.ts         → 路由守卫
  components/ lib/        → Markdown/MindMap/grading/darkMode

backend/
  api/*.py                → 12 个 Router（auth/workbooks/questions/knowledge/documents/rag/review/agent/wrong_records/stats）
  api/deps.py             → get_current_user（Bearer→JWT→User）
  services/*.py           → 业务逻辑（access 权限/CRUD/SM2/RAG/生成/Agent/stats）
  repositories/*.py       → 纯数据访问
  models/*.py             → 12 张表 ORM
  schemas/*.py            → Pydantic 请求/响应
  rag/*.py parsers/*.py   → 向量库/文档解析
  workflow/{graph,state}  → LangGraph 编排
  config.py               → pydantic-settings（.env）
通信/数据流
浏览器 → api/client.ts（/api/**，Bearer）→ FastAPI Router（get_current_user 鉴权）→ Service（access.* 做属主校验）→ Repository → SQLAlchemy → SQLite。AI 链路：Service → LLMService → DeepSeek；RAG：Service → Chroma（按 workbook_id 过滤）。

十一、问题清单（按严重程度）
P0（数据泄露/越权/严重 Bug）
[1]
严重程度：P0
文件：backend/services/stats_service.py
函数：get_stats
问题：复习卡查询 db.query(ReviewCard).join(Question).filter(workbook_id.in_(visible))
      未按 ReviewCard.user_id 过滤。
为什么：内置题库 workbook_id=0 对所有用户可见，ReviewCard 是"一人一题一卡"。
       不按 user_id 过滤会把【其他用户】对内置题的复习卡也聚合进当前用户的统计。
可能的影响：cards_total/cards_due/favorites/正确率分布/热力图被他人数据污染，
       属跨用户数据隔离缺陷（统计泄露）。
建议：查询条件加 ReviewCard.user_id == user.id（ReviewCard 本身就有 user_id 列）。
是否必须现在修复：是（P0，且修复成本一行）。
P1（核心功能 Bug / 高概率踩坑）
[2]
严重程度：P1
文件：backend/models（answer_record.py、wrong_record.py、question.py、workbook.py）
函数：delete_workbook 级联
问题：answer_records.question_id 与 wrong_records.question_id 为 ondelete=RESTRICT，
      而 questions.workbook_id 为 CASCADE。
为什么：删除练习册→级联删题→题被 answer/wrong 记录引用→RESTRICT 触发外键约束失败。
已实测确认：IntegrityError FOREIGN KEY constraint failed。
可能的影响：用户一旦在某练习册刷过题（产生答题/错题记录），该练习册将无法删除，
       DELETE /workbooks/{id} 返回 500。
建议：要么练习册也做"软删除"，要么删练习册前先删/置空相关 answer_records、
      wrong_records（或将这两处 FK 改 CASCADE/SET NULL，需迁移）。
是否必须现在修复：建议尽快（功能 Bug）；前端目前无删练习册入口，故短期不暴露，
       但 API 存在，P1 后续必踩。

[3]
严重程度：P1
文件：frontend/src/lib/markdown.ts + components/MarkdownContent.vue
函数：renderMarkdown / v-html 渲染
问题：渲染结果经 v-html 直接注入，renderMarkdown 不清洗 HTML（仅 katex 失败路径转义）。
为什么：AI 生成题/解析、举一反三、用户导入文档内容都可能含 HTML/<script>，
       将被原样注入 DOM。
可能的影响：XSS 注入（本机工具风险中等，但 AI 产出不可控，属真实注入面）。
建议：渲染后过 DOMPurify（或先把输入整体 escape 再做 markdown 替换）。
是否必须现在修复：建议尽快；本机自用可降级为 P2，但 4 人协作/演示前应修。
