## 1. 设计目标

面向大学生期末复习，将课程资料自动转化为结构化学习资源：

```text
上传资料 → 知识提取 → 思维导图 → AI 出题 → AI 审题 → 刷题（FSRS-6）→ 错题 → 诊断建议
```

统一智能入口：**助手·导师 Agent**（ReAct 主 Agent），用户以自然语言驱动上述全部能力。

---

## 2. 系统总体架构

```text
┌─────────────────────────────────────────────────────┐
│ 表现层：Vue 3（11 页面 + AI 助手聊天）                  │
├─────────────────────────────────────────────────────┤
│ API 层：FastAPI，/api 前缀，26 条路由                   │
├─────────────────────────────────────────────────────┤
│ Agent 层：主 Agent（ReAct 循环）+ 工具层（读写分级）      │
├─────────────────────────────────────────────────────┤
│ 领域层：知识专家 / 出题专家 / 教练专家（内部均为 Pipeline）│
├─────────────────────────────────────────────────────┤
│ 业务服务层：资料/题库/判题/FSRS/错题/统计（纯确定性）     │
├─────────────────────────────────────────────────────┤
│ 数据层：SQLite（12 表）+ Chroma（向量）                 │
├─────────────────────────────────────────────────────┤
│ AI 模型：DeepSeek（文本/function calling）+ 千问视觉（预留）│
└─────────────────────────────────────────────────────┘
```

调用方向（严格分层，下层不依赖上层）：

```text
API → Service → Repository → Database
API → Agent Service → 主 Agent（ReAct）→ 工具/专家子图 → Service → Repository
```

## 3. 功能模块

| 模块 | 功能 | 实现形态 |
|---|---|---|
| 用户 | 注册/登录/JWT+refresh 轮换 | Service |
| 资料 | 上传/解析（PDF/Word/PPT/MD/TXT/HTML）/自动索引 | Service + parsers |
| 知识 | 知识点提取、层级、思维导图 | 知识专家 Pipeline |
| 题库 | CRUD/软删/收藏/搜索/举一反三/AI 生成 | Service + 出题专家 Pipeline |
| 刷题 | 三模式、自动判题、简答 LLM 判分降级、FSRS-6 调度 | Service |
| 错题 | 自动记录、编辑、筛选、收藏、AI 错因分析 | Service + 教练专家 |
| 统计 | 掌握度/热力图聚合（/api/stats） | Service |
| AI 助手 | 开放式对话、任务编排、辅导、导航 | 主 Agent（ReAct） |

## 4. Agent 架构（核心）

```text
                        用户
                          ↓
        ┌─────────────────────────────────┐
        │  助手·导师 Agent（主，唯一 ReAct）  │
        └───────┬─────────┬─────────┬──────┘
                ↓         ↓         ↓
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 知识专家  │ │ 出题专家  │ │ 教练专家  │
        │内部Pipeline│ │内部Pipeline│ │Pipeline+跨专家│
        └──────────┘ └──────────┘ └──────────┘
                ↓         ↓         ↓
            解析/RAG   生成→审题    错题/统计/FSRS-6
            /导图服务   回环≤2      确定性服务层
```

| Agent | 职责 | 输入 | 输出 | 不负责 |
|---|---|---|---|---|
| 助手·导师（主） | 意图理解、任务编排、答疑、辅导、导航 | 自然语言+对话历史+workbook+页面上下文 | reply+steps[]+proposals[] | SQL、出题、审题、诊断 |
| 知识专家 | 文档理解→知识点→层级→导图 | 解析后章节文本 | 知识树+导图 | 与用户对话 |
| 出题专家 | 按主题出题并保质入库 | 主题+题型+数量+难度 | approved 题目+审题报告 | 诊断、调度 |
| 教练专家 | 错因归因→诊断→调出题专家出补救题→建议 | 用户 ID+时间范围 | 诊断+补救题+建议 | 调度、对话 |

**三条红线**：① 决策只在主 Agent（专家内部步骤固定，回环上限是规则）；② 写操作两阶段确认（propose→confirm）；③ LLM 输出三层校验后才入库。

## 5. 核心数据流

```text
资料流：文件 → 解析 → 知识专家 → 知识树/导图 → 自动索引 → Chroma
题目流：主题 → RAG 检索 → 生成 → 三层校验 → 审题 →(≤2 回环)→ 题库
学习流：作答 → 判题 → AnswerRecord → FSRS-6 调度 → 复习卡到期
        答错 → WrongRecord → 教练专家 → 诊断/补救题
对话流：消息+context → 主 Agent ReAct → 工具/专家 → reply+steps+proposals
```

## 6. 技术架构

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + Vite + Pinia（端口 5175，Vite 代理 /api） |
| 后端 | FastAPI（端口 8080）+ SQLAlchemy 2.0 + Alembic |
| Agent | LangGraph（create_react_agent + 专家子图） |
| 业务库 | SQLite（12 表）　向量库 Chroma　嵌入 本地 ONNX MiniLM（免 key） |
| 调度 | FSRS-6（py-fsrs 6.3.2） |
| 模型 | DeepSeek（文本+function calling）、千问视觉（图片，预留） |

部署：开发态前后端分离本地启动（启动.bat 一键）；无外部中间件依赖。

---

## 7. 安全与权限

密码只存 Hash；密钥一律 .env；上传校验扩展名/MIME/大小（≤10MB）；Agent 工具读写分级，写操作用户确认；禁止 LLM 直连 SQL/文件系统/系统命令。
